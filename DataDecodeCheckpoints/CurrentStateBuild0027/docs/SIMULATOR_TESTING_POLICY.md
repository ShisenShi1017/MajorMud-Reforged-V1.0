# Simulator Testing Policy

## Evidence labels

- `verified_from_data`: directly supported by decoded data, imported database, or source.
- `simulator_verified`: generated by an actual executable simulator test with committed log output.
- `expected_model`: generated as a scenario/matrix target or projection, not executed as simulator behavior.
- `strong_candidate`: supported by repeated data/source patterns but not proven as runtime behavior.
- `weak_candidate`: plausible but insufficient evidence.
- `runtime_required`: needs original runtime observation or unrecovered engine code.

## Rules

1. Do not promote expected-model rows to simulator-verified unless executable tests run.
2. Do not promote simulator-verified behavior to original-runtime-verified.
3. Every formula claim must identify its evidence label.
4. Every skipped test must say whether it is missing code, missing data, or runtime_required.
5. Prefer honest partial coverage over fabricated completeness.
