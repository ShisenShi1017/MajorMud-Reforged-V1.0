# Runtime-0015 — World Runtime Integration

Runtime-0015 connects the previously built offline runtime subsystems into a single world driver. This milestone deliberately comes before networking/dedicated server work so the game world can run locally and deterministically first.

## Added

- `Runtime/world_integration/world_runtime.py`
- `Runtime/world_integration/__init__.py`
- `Sim/validators/validate_world_integration.py`
- `Reports/world_integration_report_0015.json`
- `Saves/` output generated by validation

## What this milestone proves

The runtime can now:

1. Load canonical `/Data` through `DataRuntime`.
2. Create a deterministic offline `WorldState`.
3. Seed a playable validation world with a player, monsters, and ground items.
4. Execute commands through the Runtime-0012 command dispatcher.
5. Advance the scheduler/tick pipeline.
6. Trigger AI/combat/status/regen/spawn/NPC/cleanup hooks.
7. Persist world, character, and snapshot saves through Runtime-0014.
8. Emit a validation report.

## Classic accuracy boundary

Runtime-0015 is not a claim that classic MajorMUD hidden timing, combat, AI, scripting, quest, or save-file behavior is fully reproduced. The world runtime is a Reforged integration shell that carries provenance markers and delegates formula behavior to the evidence-gated subsystem modes.

## Why this milestone exists

The project should not jump directly from independent calculators to networking. Runtime-0015 creates the offline world runner that a future dedicated server can wrap without rewriting the actual gameplay runtime.

## Next milestone

Runtime-0016 should become Network Sessions / Dedicated Server Wrapper. It should not replace the offline world runtime; it should drive `WorldRuntime` through connected sessions.
